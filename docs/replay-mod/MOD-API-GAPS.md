# General mod API and native-route gaps from the Replay probe

Evidence is from publisher-verified SDK `68b51161354df882c903467bd891a7996e08c11f`, mixins `e59da9094f0c2fdda6c627fe9eff22dec6a906f0`. `PLAN.md` distinguishes build admission, documented refusal, and unrun behavior. No engine seam or fix is implemented or presumed approved. Prefer existing hooks and the smallest general tool or API correction; no feature-named registries, hooks, or fields.

| ID | Gap and evidence | General proposal / decision needed |
| --- | --- | --- |
| G1 | **Receive boundary below the game crate.** `crates/sunrise-client/src/net.rs:1127,1140–1167` (`receive_play`, compiled by `sunrise-client-lib`) owns receive ID/body before the worker handles or transforms packets, but is absent from the signed `functions.json`. The `client_packet` contract in `crates/sunrise-mod-vocab/src/hooks/client_packet.rs:4–24` is game-thread, decoded type ID and custom bytes only; keep-alive, bundle delimiters, reconfiguration, resource-pack events, etc. are not delivered. `raw_ingress.rs:8–18,39–84,250–260` further shows why wrapping `handle_packet` is narrower than even the game queue. | Evaluate opt-in exact-build replacement at a bounded lower-crate packet producer, with original immutable ID/body, connection identity, direction/phase and receipt timestamp; avoid new linked dispatch or per-packet copying when unarmed. For a genuinely shared API need (passive protocol diagnostics and conformance fixtures as well as local archives), review a read-only protocol observation boundary separately; keep the documented semantics of the current `client_packet` hook. For a first game-side MVP explicitly disclose partial capture, rather than inferring original bytes/time from a typed decoded value. |
| G2 | **WRAP rejected before binding/encoding could compile.** Signed SDK `native-build` for exact selector `self.handle_packet` in `sunrise_client::game::remote::raw_ingress::Game::poll_remote_events`, and `self.session.poll` in `sunrise_client::game::remote::raw_ingress::Remote::receive_credited_backlog`, each returned `E_UNSUPPORTED_MACRO: macro identity is ambiguous; use an unshadowed absolute standard path`. The latter function has existing unqualified `matches!`; the diagnostic does not point to a macro span in the original source. This is distinct from the known `?`-receiver issue #2521. | Minimize a generic case where the target contains unqualified macros unrelated to a selected operation. If preserving the original token stream/lexical macro context can guarantee equivalence, admit that transformation; otherwise diagnose the precise source macro and offer a qualification fix without changing its identity. Do not assume `HEAD` or `OVERWRITE` bypasses this guard; try the narrow indexed `Game::observe_client_packet` separately. |
| G3 | **View orientation lacks roll.** `camera_pose` compiled with position/yaw/pitch; its documented contract in `crates/sunrise-mod-vocab/src/hooks/camera_pose.rs:4–10` and dispatch at `crates/sunrise-client/src/game/native_hooks/camera_pose.rs:11–18` do not carry roll. `compute_fov` is independent. The old feature’s roll at `crates/sunrise-client/src/game.rs:5442` is not general or a valid target. | If the existing camera angle event is extended, add finite-validated roll about the forward axis at the existing `ViewportEvent.ComputeCameraAngles` moment and carry it consistently through visible orientation and picking/frustum decisions according to the public contract. Follow hook version/catalog rules. No second camera provider. |
| G4 | **Playback must own its transport and view.** The ordinary memory route `connect_remote_session` (`crates/sunrise-client/src/game/network/remote/mod.rs:951,998–1007`) exists but isn't exercised here. Game-thread `client_packet_send` skips worker and phase-specific traffic (`crates/sunrise-mod-vocab/src/hooks/client_packet_send.rs:4–18`); the writer is not made read-only by a GUI flag or cancel hook. No API admission, seek/reset or resource-ready proof. | Prototype a local-only synthetic memory peer and no route to a real endpoint first; use generic client lifecycle and close. If the replacement route cannot create/manage it without reaching private internals, ask for a generally useful generation-bound local connection/start operation on existing dispatch, with no account/service start, explicit send sink/control-plane treatment and a clear lifetime. A local protocol fixture or diagnostic trace are other possible consumers. Don't propose a new packet-provider registry merely because playback is unrun. |
| G5 | **Input ownership and in-play pointer geometry.** `key_mapping_pre` (`crates/sunrise-mod-vocab/src/hooks/key_mapping_pre.rs:4–12`) is physical, active only while playing/no screen, absent for pad/mod-fed presses. `mouse_button_pre` has raw button/modifier fields but no GUI position; `screen_mouse_*_pre` has screen pointer coordinates but no playing-view dispatch, and no synthetic/pad clicks. No public capture/release operation was found in this slice. | Continue using existing mod screens and focus/widgets where possible. If a free-flying view actually needs an input grant, route a single owning client’s normalized look/actions, capture and release/focus-loss, including drag/held-state cleanup, before regular gameplay. General input work such as #2498 is relevant; no mod second backend, engine feature slot, or fake click injection. |
| G6 | **Owned screen from an existing title/pause menu.** `mod_screen_open` (`crates/sunrise-client/src/game/native_hooks/base.rs:4550–4575`) rejects an already-open non-mod screen; its guard blocks title (`native_hooks/shared.rs:227–235,3693–3705`). Title settlement does not turn `ModScreen` into a title child (`:314–353`). The screen press callback takes `&dyn ClientHost`; an attempted direct call failed `E0596`, before the fixture switched to a mutating client tick callback. | Use the screen hook’s existing overlay path where viable. If lifecycle/focus/back-stack requires ownership, extend the existing screen operation with explicitly allowed child transitions and restoring owner/parent IDs, plus a generic action/request to defer resource-dependent work until ready. Route menu buttons via existing widgets or a general screen-init/widget operation if needed. Don't replace the entire pause menu to obtain one button. |

No new geometry pathway is required to compile the line submission. No new command registry is indicated by the SDK: both usage pairs link through the existing hooks, with actual grammar/dispatch and collisions still to test after built-in Studio is removed. A locked API-only fixture and two WRAP refusals are not evidence that the unrun gaps above are the only possible blockers.
